# caucus-race 仕様書（ドラフト v0.1）

## 1. 目的

AI エージェントが自律的にソフトウェア開発を進められるよう、スプリント（アジャイル開発）をメタファーとして開発のオーケストレーションを行う。

現状は人間がカードを起票・整理し、ストーリーやタスクの粒度でエージェントを起動している。開発の起点が人間にあるため、人間の作業量が開発速度の上限になっている。caucus-race では、ストーリーの洗い出しからスプリント計画、実装・テストの実行までを AI が進め、人間の関与を次の 2 点に限定する。

1. **スプリント計画の承認**（スパイクへの回答を含む）
2. **スプリントレビュー**（成果物を実際に操作して確認し、フィードバックを返す）

## 2. スコープ

### 対象とする責務

- 複数プロジェクトの並行管理
- バックログ・スプリント・ストーリー・タスク・スパイクの管理
- スプリントのフェーズ遷移（プランニング → 実行 → レビュー → 終了）の制御
- 外部の開発ループ（che vuoi）の呼び出しと、その結果の記録
- 人間の判断が必要な箇所（承認・スパイク・レビュー）の提示と、回答の受け付け
- レビューのフィードバックを次のストーリーへ変換すること

### 対象外とする責務

- コードの実装・テストそのもの（che vuoi が担当する）
- レトロスペクティブの活用方法（記録の置き場だけ用意し、活用方法は後で検討する）

## 3. 用語

| 用語 | 定義 |
|---|---|
| プロジェクト | 管理の最上位単位。1 つの開発対象（リポジトリ）に対応する |
| バックログ | プロジェクトに属し、まだスプリントに割り当てられていないストーリーの集合 |
| スプリント | 一定の目標（スプリントゴール）に向けて、選んだストーリーを実装する期間 |
| スプリントゴール | スプリント終了時に達成されている状態を言葉で表したもの |
| ストーリー | 利用者にとって価値のある変更の単位。スプリント内で実装・テストされる |
| タスク | ストーリーを達成するために必要な具体的な作業 |
| スパイク | ストーリーの実装前に人間が決定しなければならない検討事項。AI が自分で決定できないもの |
| フィードバック | スプリントレビューで人間が返す指摘。次のストーリーの元になる |
| レトロ記録 | スプリントを通じて気づいたことや反省点の記録 |
| 実行器（Executor） | ストーリーの実装・テストを担う外部の開発ループ。当面は che vuoi |

## 4. データ構造

```
Project
 ├─ Story（バックログ: sprint 未割り当て）
 ├─ Sprint
 │   ├─ goal
 │   ├─ Story（このスプリントに割り当て）
 │   │   ├─ Task *
 │   │   └─ Spike *
 │   ├─ Feedback *   （レビューで登録。次のストーリーへ変換）
 │   └─ RetroNote *
 └─ ...
```

- メモでは「スプリントは複数のストーリーで構成される」としているが、ストーリーはスプリント計画より前に存在する（バックログ）。そのため **ストーリーはプロジェクトに属し、スプリントへは任意で割り当てる** 構造にする。
- 各エンティティの属性は設計書（`docs/design.md`）に記載する。

## 5. フェーズと人間の関与

```
 ┌──────────── プランニング ────────────┐   ┌──────── スプリント ────────┐
 ストーリー洗い出し → ストーリー選定 → 計画作成 → [人間] スパイク回答・計画承認
                                                     ↓
                                              ストーリーごとに実装・テスト
                                                     ↓
                                          [人間] スプリントレビュー → フィードバック
                                                     ↓
                                              レトロ記録 → スプリント終了
                                                     ↓
                                       フィードバックを次のバックログへ
```

### 5.1 プランニング

1. **ストーリーの洗い出し（AI）**
   バックログに、そのスプリントで実装すべきストーリーの候補を用意する。ストーリーの入力元は次のとおり。
   - 人間が直接起票したもの
   - 前スプリントのフィードバックから変換したもの
   - 前スプリントの実行中に AI が見つけた範囲外の課題（che vuoi の `proposals` など）
   - AI がプロジェクトの目標や現状から提案したもの
2. **ストーリーの選定とスプリント計画の作成（AI）**
   バックログからストーリーを選び、スプリントゴールを決める。選んだストーリーごとにタスクへ分解し、人間の決定が必要な事項をスパイクとして洗い出す。
3. **スパイクへの回答（人間）**
   人間がスパイクに回答する。回答はストーリーの決定事項として記録し、必要に応じて AI がタスクを見直す。回答の結果、ストーリーを今回のスプリントから外す判断もできる。
4. **計画の承認（人間）**
   スプリントゴールと、含まれるストーリー・タスクを確認して承認する。差し戻す場合はコメントを付け、AI が計画を作り直す。

**開始条件:** 計画が承認済みであり、かつスプリントに含まれる全ストーリーに未解決のスパイクが残っていないこと。

### 5.2 スプリント実行

1. ストーリーを 1 件ずつ実行器（che vuoi）に渡し、実装とテストを行う。
2. 実行結果（成功・中断・エラー、要約、変更内容、範囲外の課題）をストーリーに記録する。
3. 全ストーリーが終了状態（完了・失敗・中断）になると、スプリントレビューへ進む。

実行中に人間の判断が必要な事態が発生した場合（実行器が `blocked` を返した場合など）は、該当ストーリーを「中断」にしてスパイクを起票し、残りのストーリーは続行する。中断したストーリーはレビュー時に扱いを決める。

- 実行器に渡す単位はストーリーとする。タスクはブリーフ内のチェックリストとして渡す。
- ストーリーは依存関係を持たず、優先順に直列で実行する。
- スプリントは期間で区切らず、選んだストーリーがすべて終了するまでとする。1 スプリントに含められるストーリー数には上限（既定 5）を設ける。

### 5.2.1 ブランチとコミット

ブランチの管理は caucus-race が行う。

- スプリント開始時に、プロジェクトのベースブランチ（既定 `main`）からスプリント用ブランチ（`caucus/sprint-<n>`）を作成する。開始時点で作業ツリーに未コミットの変更がある場合は開始しない。
- 実行器（vuoi のワークフロー）が自分でコミットすることは禁止しない。
- ストーリーの実行後、作業ツリーに未コミットの変更が残っていれば caucus-race がコミットする。
- 完了しなかったストーリー（失敗・中断）の変更は、退避用ブランチ（`caucus/wip/<story_id>`）に保存し、スプリント用ブランチはそのストーリーの実行前の状態に戻す。次のストーリーに途中の変更を持ち込まないためである。
- スプリント用ブランチのベースブランチへのマージは、レビュー後に人間が行う。

### 5.3 スプリントレビュー（人間）

1. caucus-race が、スプリントゴール・ストーリーごとの結果・成果物の確認方法をまとめたレビュー資料を提示する。
2. 人間が成果物を実際に操作して確認し、フィードバックを登録する。
3. フィードバックは AI が次のストーリーへ変換し、バックログに追加する。
4. 人間がレビューの完了を宣言すると、スプリントは終了する。

### 5.4 レトロスペクティブ

スプリント中・終了時に気づいたことや反省点を記録する。記録の活用方法は後で検討する。当面は、AI と人間がそれぞれ記録を追加できる置き場だけ用意する。

## 6. 機能要件

### プロジェクト

- F-1: プロジェクトを登録・一覧・更新できる。プロジェクトは開発対象のリポジトリのパスを持つ。
- F-2: 複数プロジェクトのスプリントを並行して進められる。1 プロジェクトで同時に実行中にできるスプリントは 1 つとする。

### バックログ・ストーリー

- F-3: ストーリーを起票・編集・削除できる（人間・AI の両方）。
- F-4: ストーリーには起票元（人間 / AI / フィードバック / 実行器の提案）を記録する。
- F-5: ストーリーは受け入れ条件を持つ。

### プランニング

- F-6: AI がバックログからストーリーを選び、スプリントゴール付きのスプリント計画を作成できる。
- F-7: AI がストーリーをタスクに分解できる。
- F-8: AI がストーリーごとにスパイクを起票できる。
- F-9: 人間がスパイクに回答できる。回答済みのスパイクは解決済みになる。
- F-10: 人間がスプリント計画を承認・差し戻しできる。
- F-11: 開始条件（§5.1）を満たさない場合、スプリントを開始できない。

### スプリント実行

- F-12: スプリントを開始すると、ストーリーを順に実行器へ渡す。
- F-13: 実行器の結果をストーリーに記録する。
- F-14: 実行は中断・再開できる（プロセスが止まっても、状態から再開できる）。

### レビュー

- F-15: レビュー資料を生成できる。
- F-16: 人間がフィードバックを登録できる。
- F-17: フィードバックからストーリーを生成し、バックログに追加できる。
- F-18: 人間がレビューを完了し、スプリントを終了できる。

### レトロ

- F-19: レトロ記録を追加・一覧できる。

### 通知・監査

- F-20: 人間の対応待ち（スパイク回答、計画承認、レビュー）が発生したら、人間に知らせる。
- F-21: 状態遷移と AI・人間の操作をイベントとして記録し、後から追跡できる。

## 7. 非機能要件

- **再開可能性:** 全状態を永続化し、プロセスが停止しても途中から再開できる。
- **追跡可能性:** 誰が（どの AI・人間が）いつ何を決定したかを残す。
- **実行器の差し替え:** 実行器はインターフェースで分離し、che vuoi 以外や、テスト用の偽実行器に差し替えられる。
- **ローカル動作:** 当面は 1 人の利用者が手元の環境で動かすことを前提とする。

## 8. 想定する利用の流れ（例）

```
$ caucus project add chevuoi --repo ~/projects/chevuoi
$ caucus plan chevuoi            # AI がストーリー選定・計画・スパイクを作成
$ caucus spikes chevuoi          # 未解決のスパイクを一覧
$ caucus spike answer SP-12 "認証は OAuth に統一する"
$ caucus sprint approve chevuoi  # 計画を承認
$ caucus sprint start chevuoi    # 実行開始（バックグラウンド）
...
$ caucus review chevuoi          # レビュー資料を表示
$ caucus feedback add chevuoi "一覧画面の並び順が逆"
$ caucus review done chevuoi     # スプリント終了、フィードバックをバックログへ
```

コマンド体系は仮のもの。UI の形態は §9 で検討する。
